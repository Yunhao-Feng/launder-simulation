### 1. Precisely model the 8 patterns (conceptual definitions)

Please use these exact structural definitions (these matter for how we later generate transactions and label them):

1. **Fan-out pattern of a vertex v**

   * Let v be a single source account.
   * v has **k ≥ 2 distinct outgoing neighbors** w₁, w₂, …, wₖ.
   * For each neighbor wᵢ there is at least one edge (transaction) v → wᵢ, typically within a short time window, representing splitting a lump sum into multiple smaller transfers.
   * Intuition: split a large amount in v across several other accounts to reduce detection.

2. **Fan-in pattern of a vertex v**

   * v is now a sink account.
   * v has **k ≥ 2 distinct incoming neighbors** u₁, u₂, …, uₖ.
   * For each neighbor uᵢ there is at least one edge uᵢ → v, typically within a short time window, representing consolidation.
   * Intuition: many smaller inputs flowing into a single account.

3. **Gather-scatter pattern at a single vertex v**

   * v simultaneously participates in:

     * a fan-in pattern (multiple distinct predecessors send money into v), and
     * a fan-out pattern (v sends money out to multiple distinct successors).
   * So v has k_in ≥ 2 distinct incoming neighbors and k_out ≥ 2 distinct outgoing neighbors.
   * Intuition: v acts as a hub that gathers funds from many sources and then redistributes them further.

4. **Scatter-gather pattern between vertices v and u via shared intermediates**

   * There is a **fan-out** from a vertex v to a set of intermediate vertices M = {m₁, …, mₖ} (k ≥ 2), i.e. edges v → mᵢ.
   * There is a **fan-in** into a (possibly different) vertex u from exactly the same set of intermediates M, i.e. edges mᵢ → u.
   * The set of intermediate vertices on the fan-out and fan-in sides is the same: v → M → u.
   * Intuition: v scatters funds across intermediaries that later reconverge into u.

5. **Simple cycle pattern**

   * A sequence of distinct vertices v₁, v₂, …, v_L (L ≥ 3) such that:

     * There are edges v₁ → v₂, v₂ → v₃, …, v_{L-1} → v_L, v_L → v₁.
     * Aside from v₁ == v_L (start/end), **no other vertex is repeated** in the cycle.
   * Intuition: funds move around a loop and come back to (one of) their origin(s).

6. **Random pattern**

   * A **random walk among accounts controlled by the same entity**.
   * Funds are moved through a sequence of accounts, but **do not return** to the original account.
   * Structurally similar to a simple path (no repeated nodes, or at least no return to the starting node), possibly with variable length.
   * Intuition: move money through a chain of controlled accounts without forming a recognizable pattern like a clean cycle.

7. **Bipartite pattern**

   * Two disjoint sets of vertices:

     * Input accounts: A = {a₁, …, a_m}
     * Output accounts: B = {b₁, …, b_n}
   * Edges only go **from A to B**: aᵢ → bⱼ.
   * No edges within A, no edges within B, and no edges B → A as part of the pattern.
   * Intuition: a set of senders pay a set of receivers in a relatively dense, bipartite fashion.

8. **Stack pattern**

   * A **multi-layer bipartite structure**, essentially stacking bipartite patterns:

     * First layer: A → B
     * Second layer: B → C
     * Optionally more layers: C → D, etc.
   * Each layer is bipartite (edges only go from previous-layer set to next-layer set), and layers are chained.
   * Intuition: pass funds through multiple “shell layers” (A to B to C, …) to further obfuscate origin.

You do not need to implement complex subgraph mining.
You **do** need to be able to generate synthetic transaction sequences that clearly follow these structures and label them.
